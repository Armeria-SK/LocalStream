# LocalStream

Windows PC の画面と音声を、同じ LAN 内のテレビ・スマホ・Mac・Nintendo Switch に低遅延で配信するストリーミングツールです。
受信側からは PC のマウス・キーボード・ゲームパッドを操作できます。

- PC 側（サーバー）で画面をキャプチャし、GPU のハードウェアエンコーダ（NVIDIA NVENC 優先）で HEVC または H.264 に圧縮して UDP で送ります。
- 受信側（クライアント）はハードウェアデコーダで表示します。受信側で映像を溜める待ち時間（ジッタバッファ）は持たず、届いたフレームをすぐ表示します。
- 通信はすべてローカルネットワーク内で完結し、外部のサーバーは使いません。

## 構成

| フォルダ | 内容 |

## 必要なもの

- **PC**：Windows 10/11（x64）、ハードウェアエンコーダ付きの GPU（NVIDIA 推奨。AMD / Intel は Media Foundation 経由の H.264）、[.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)
- **テレビ / スマホ**：Android 8.0 以上（ゲームモード要求は Android 11 以上）
- **ネットワーク**：PC と受信機が同じ LAN にあること。Wi-Fi なら 5 GHz 帯、可能なら受信機は有線 LAN を推奨
- 任意：ゲームパッドを使う場合は PC に [ViGEmBus](https://github.com/nefarius/ViGEmBus/releases/latest)

## クイックスタート

### 1. PC でサーバーを起動する

```bat
server\build-and-run.bat
```

ビルドしてから起動します。初回は Windows ファイアウォールの確認が出るので、**プライベートネットワーク**で許可してください。
更新後に使うときは、先に最新のソースを取り込んでから実行します（bat は取り込みまでは行いません）。

```bash
git pull
```

起動中に bat をもう一度実行すると、実行中のファイルを上書きできずビルドに失敗します。先に Ctrl+C で止めてください。

### 2. テレビ / スマホにアプリを入れる

GitHub Actions の「Android APK」ワークフローの成果物（`localstream-release-apk`）から APK を取得してインストールします。
自分でビルドする場合は `android/` を Android Studio で開くか、`./gradlew assembleRelease` を実行します（JDK 17 が必要）。

### 3. 接続する

1. アプリを開くと、LAN 内の PC が自動で一覧に出ます（出ない場合は IP アドレスを手入力）。
2. 初回は PC の画面（コンソールまたはダッシュボード）に表示される **6 桁の PIN** をアプリに入力します。以降は自動で接続されます。
3. 配信が始まります。

### 4. スマホをコントローラにする（任意）

テレビで配信中は、次の 2 通りでスマホを操作に使えます。

- **ブラウザ**：テレビに表示される `http://<テレビのIP>:47820` をスマホで開き、テレビに出ている 4 桁のコードを入力します。スマホがタッチパッドになります。
- **アプリ**：テレビで配信中に、スマホの LocalStream アプリから同じ PC に接続します。画面出力が使用中である旨が表示されるので、「コントローラとして接続」を選びます。タッチパッドと文字入力（日本語可）が使えます。

どちらの方法でも、テレビ側にカーソルが表示されて追従します。PC 側でカーソルが消える場面（動画の全画面表示など）では、テレビ側のカーソルも消えます。

## 主な機能

- **映像**：HEVC / H.264 を自動選択します（受信機のハードウェアデコーダと GPU が対応していれば HEVC）。60 fps、ネイティブ解像度または 720p に対応します。
- **低遅延の工夫**
  - エンコーダ設定：B フレームなし、1 フレーム分の VBV
  - パケット欠損対策：前方誤り訂正（XOR FEC）で欠けたパケットを復元します。復元できない欠損は、キーフレームを待たずに画面を少しずつ描き直して回復します（イントラリフレッシュ）。
  - 受信側：デコーダをリアルタイム優先で動かし、テレビにはゲームモードを要求します。
- **ビットレート自動調整**：混雑を検知すると下げ、回復時は上限との差の半分ずつ上げます（初期値 16 Mbps、上限は既定で 50 Mbps）。
- **音声**：PC の再生音を 48 kHz ステレオで送ります（5 ms 単位）。
- **入力**：マウス、キーボード（物理配列どおり、日本語テキストも可）、ゲームパッド（仮想 Xbox 360 コントローラ、最大 4 台）
- **Hide**：テレビ側の操作パネルを隠して映像だけにします。リモコンの D-pad でカーソルを操作でき、Back で操作パネルが戻ります。
- **統計表示**：配信画面の状態表示（チップ）をタップすると、詳細な診断情報が出ます。

## 統計表示の見方（Android）

| 行 | 内容 |
|---|---|
| `VIDEO` | 解像度・fps・使用中のコーデック（`offered` はアプリが PC に提示したコーデック）・欠損からの回復方式 |
| `ENC` | PC 側のエンコーダと目標ビットレート |
| `DEC` | テレビのデコーダ名、低遅延モード・チップ別の低遅延設定・リアルタイム優先度が有効か |
| `TV` | ゲームモード要求の結果 |
| `MOUSE` / `CURSOR` | マウス入力の状態と、カーソル表示の診断 |

## 設定

サーバーの主な起動オプション（詳細は [`server/README.md`](server/README.md)）:

| オプション | 内容 |
|---|---|
| `--quality native\|720p` | 既定の解像度 |
| `--max-bitrate-kbps N` | ビットレート上限（既定 50000） |
| `--headless` | ログをファイルに出して常駐 |
| `--install-autostart` / `--uninstall-autostart` | ログオン時の自動起動を登録 / 解除 |
| `--web-port N` / `--no-web` / `--web-lan` | Web ダッシュボード（既定 `http://127.0.0.1:47810/`） |

環境変数:

| 変数 | 内容 |
|---|---|
| `LOCALSTREAM_ENCODER=nvenc\|mf` | エンコーダを固定（NVENC 限定 / Media Foundation 強制） |
| `LOCALSTREAM_CODEC=h264` | HEVC を使わず H.264 に固定 |

## ポート

| ポート | 用途 |
|---|---|
| UDP 47800 | PC の自動検出 |
| TCP 47801 | 制御（接続・ペアリング・入力） |
| UDP 47802 | 映像（カーソル位置もここで送る） |
| UDP 47803 | 音声 |
| TCP 47810 | Web ダッシュボード（既定は PC 内からのみ） |
| TCP 47820 | テレビ側：スマホのブラウザ用タッチパッド |

## トラブルシューティング

- **新機能が効かない**：PC のサーバーとテレビのアプリの両方が最新か確認してください。
  配信開始時に PC のコンソールに `streaming started: ... (native, hevc, refresh recovery)` のようにコーデックが出ていれば、サーバーは新しい版です。
- **HEVC にならない**：
  - テレビの `VIDEO` 行が `offered h264` の場合は、テレビに条件を満たす HEVC デコーダがありません。
  - `offered hevc/h264` なのに `H264` の場合は、PC 側で HEVC を開始できていません（サーバーのログ `localstream.app.log` に理由が出ます）。
- **遅延が大きい**：テレビの `TV` 行でゲームモードを確認してください。Wi-Fi の混雑が原因のときは `--max-bitrate-kbps` を下げると改善します。
- **昇格したアプリを操作できない**：Windows の仕様上、管理者権限で動くアプリへ入力するにはサーバーも管理者権限で動かす必要があります。
